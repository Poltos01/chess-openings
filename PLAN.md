# PLAN — контракт и решения

Бриф для продолжения работы в новой сессии. Читать вместе с `README.md`.

## Решения (согласованы)

| Вопрос | Решение |
|---|---|
| Сайт или приложение | статический сайт (JS без сборки) |
| Источник | дампы Lichess, CC0, **без токенов** |
| Период v1 | октябрь 2026, потом +1 месяц/прогон |
| Гранулярность дат | месяц (день невозможен в принципе) |
| Глубина | пары первых ходов + ECO-названия |
| Сетка рейтинга | по 100 очков, два режима: `avg` и `strict` |
| Фильтр разрыва | `|Δ|>80` отброшено, кроме `max(elo)≥2400` |
| Ничьи | входят: `score=(W+0.5D)/N`, W/D/L показываются |
| Хостинг | GitHub Actions + Pages, репо публичный |

## Схема БД (db/openings.sqlite)

```
opening_stats(month, speed, band, mode, kind, name) -> n, w, d, l   [PK без rowid]
  month : '2026-10'
  speed : ultraBullet|bullet|blitz|rapid|classical|correspondence
  band  : 0,100,...,2900  (нижняя граница 100-окна)
  mode  : 'avg' (среднее двух рейтингов) | 'strict' (оба в бэнде)
  kind  : 'pair' ('1.e4 c5') | 'eco' ('B20 Sicilian Defense')
  w/d/l : результат белых
```

## Формат JSON (site/data/)

```
index.json                                  {months, speeds, bands, slices, generated_at}
<month>/<speed>/<band>.json   {meta:{...totals_avg,totals_strict}, avg:{pair:[],eco:[]}, strict:{...}}
запись в списке: [name, n, w, d, l]
```

UI грузит один срез на выбранные месяц/контроль/бэнд, считает score и Δ к базе на клиенте.

## Проверенные факты (не переисследовать)

- `explorer.lichess.org` требует OAuth2-токен; без него 401, кроме кэша Cloudflare.
- Эксплорер: бакеты только по 200 очков, `ratings=1100` молча округляется до `1000`.
- Эксплорер отдаёт 0 партий за текущий месяц — свежее закрытого месяца данных нет.
- `/player` на эксплорере отдаёт 504 — не использовать.
- Дамп = один непрерывный zstd-поток: Range-нарезка невозможна (середина файла → 0 партий).
- Скорость ingest после оптимизации: ~49 тыс. партий/с (было 2.2 тыс. из-за копирования буфера).
